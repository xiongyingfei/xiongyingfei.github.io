# 课后更新网站

2026 秋季软件分析：数据在 `_data/SA_new/_2026.yaml`，页面在 `SA_new/2026/`。

1. 将新课件放入对应学期的 `slides/`，去掉下载产生的 `(1)` 等重复编号；从可见正文读取标题和完整作业题目，公式、代码和图表按需看原页，不以可能过时的 PDF 元数据为标题。项目入门、实验手册等项目材料链接放在该学期 `materials.md` 的对应项目部分，不单独记作讲课课次。
2. 更新 YAML 的 `lectures`：上课日期、课件标题及文件名、完整作业题目、截止时间。截止时间遵循项目根目录 `AGENTS.md` 的默认规则及延期例外；用户本次明确指定的时间优先。每条主要求一个 `text`；提醒、排除清单和“无作业”等说明项也用 `text`，并加 `note: true`，让页面区别呈现且保留原有顺序。不要把教学计划 `schedule` 当成已发布课次。
3. 核对本次题目、日期和链接，提交改动；已获发布授权时推送，确认上线后给出页面链接。

本地发布验证使用原 Jekyll 布局构建，并按 `.github/workflows/pages.yml` 运行 `.site-support/finalize_pages.py` 和 `.site-support/check_site.py`。构建目录须与源仓库分开；核对新增附件哈希、受影响页面中的完整题目、截止时间及链接。发布后核对对应提交的 Pages 部署和线上页面、附件。

页面规则：

- 作业页直接展示完整题目和截止时间，不放幻灯片链接，也不加“已在教学网发布”“参见课件”等说明。`assignments.md` 只保留通用规则和标题，题目由 YAML 渲染。
- 作业页共用 `_layouts/assignments.html`：每学期按 `lectures` 中含主要求的作业条目从 1 连续显示“第x次作业”；无作业或只有说明的条目不占序号。修改模板时核对软件分析和软件基础各年份的编号，并检查窄屏显示。
- 作业主要求统一不编号，每条用轻量左线与留白区分；说明保留原顺序，不使用左线。单条和多条使用同一版式。
- 首页通知由 `_includes/announcements.html` 生成，每课一行：`日期 幻灯片标题链接 作业链接 · 截止日期`。不加中括号，无作业则省略作业部分；窄屏自然换行。
